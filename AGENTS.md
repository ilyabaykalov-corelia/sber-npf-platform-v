# Инструкции для агентов: Platform V

Начать с [продукта](docs/product.md), [реализации](docs/implementation.md) и [эксплуатации](docs/operations.md). В общей папке также применяются инструкции родительского AGENTS.md.

- Это текущая интеграция хранения и процессов, а не место для новой доменной логики. Правила документов размещать в corelia-document-service, файлов — в attachment-service, процессные вызовы — в workflow-service.
- Существующие BPMN напрямую создают сущности и меняют статусы. Учитывать эти пути при смене модели; не нарушать запущенные экземпляры без плана совместимости/миграции.
- Различать Document, дочерние реквизиты, DocumentVersion, Attachment и экземпляр BPM. Новая версия сама по себе не запускает процесс и не завершает задачу.
- Сохранять уникальность публичного documentId, пары document/version и commandKey, атомарность пакетов и compare ожидаемого состояния.
- При изменении GraphQL сверять полные тела в permissions, ресурсах адаптера Corelia, BPMN и независимой тестовой фикстуре. Не заменять проверку тела только совпадением operationName.
- Не считать scopes в ac.json полной реализацией прав: учитывать условия permissions, исполнителя процесса и политики Corelia.
- Новые файлы поставки включать в .info.meta.json. Изменение docs не должно менять состав импорта.
- Не запускать seed-dictionaries.sh как общую инициализацию: он обрабатывает только первые записи, читает .env архивного BFF и содержит жёстко заданные учётные данные. Не копировать значения секретов в ответы или документацию.
- LCUI содержит старые BFF-настройки; не считать их актуальным маршрутом React → Corelia. Не менять архивный BFF без отдельного запроса.
- Проверять git status, сохранять пользовательские изменения. Для документации проверять ссылки; для модели/процессов — проверки из operations.md. Локальная упаковка и PlatformStub не доказывают работоспособность реального стенда.
- Не сбрасывать данные при установке без отдельного согласованного сценария. При изменении поведения актуализировать документацию.
